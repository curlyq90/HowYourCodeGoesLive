Survival guide

When things break

The four hiccups you'll actually hit — and the calm, boring fix for each.

🔴

A check failed (red ✗ on your PR)

Nothing is live and nothing is broken — the safety inspection just caught something. Click the red check to read the log, tell Claude Code what it said, fix it, then commit & push again. Your PR updates itself and re-runs the checks automatically.

⚙️

"It works locally but breaks on Vercel"

The #1 gotcha. Almost always a missing environment variable — a secret setting (API keys, database URL) that lives on the machine, not in your code. Your laptop has it in .env; Vercel doesn't unless you add it.

Fix: add any new env var in both places — Vercel → Settings → Environment Variables for Preview AND Production. Keep .env.example updated so you don't forget.
🔀

"Merge conflict"

Two different edits touched the same lines, and Git honestly can't guess which one you want. It doesn't lose anything — it just pauses and asks you to choose. Open the flagged file, keep the correct version (Claude Code is great at this), then commit. As a solo founder this is rare, but merging main into your branch often keeps it small.

⏪

A bad deploy went live

Stay calm — you can undo it in seconds. Every past deploy is kept. In Vercel → Deployments, pick the last one that worked and click Promote to Production (vercel rollback from the terminal does the same). Your site is instantly back to the good version while you fix the real issue on a branch.

🗄️

The one only YOU can do: manual database migrations

Some database changes in Kehilla live as hand-run SQL in prisma/migrations/manual/. Nothing runs these automatically — not GitHub, not Vercel. If a change needs one, run it against production yourself around merge time, or the live site will error even though every check was green. This has bitten the project before.
